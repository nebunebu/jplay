# jplay

`jplay` is a terminal UI for playing Jeopardy! games from
[J! Archive](https://j-archive.com). It covers the full game loop: board
navigation, clue answering with fuzzy judging, Daily Doubles, Final Jeopardy,
per-game persistence to SQLite, and an in-app stats review mode.

It has a built-in archive fetcher (`jarch`) that the browser uses directly,
and that can also be run on its own with `jplay --fetch`.

## Usage

```
jplay [game.json]          # play a jarch game JSON file directly
jplay                      # landing screen: browse the archive or open a file
jplay --stats              # stats review mode (Recent · By Category · By Value · Missed · Passed)
jplay --config             # settings screen
jplay --fetch <sub> [id]   # standalone fetcher, see below
```

All navigation accepts both vi keys (`hjkl`) and arrow keys. On the board:
`Enter` opens a clue, typing + `Enter` locks in an answer, `Esc` passes,
`y`/`n` confirm or reject a close fuzzy match, `Space` dismisses the reveal.
`q` backs out (with confirmation mid-game; abandoned games are not recorded).
In the archive browser, `f` caches a game without playing it.

## Fetching (`jplay --fetch`)

The fetcher pulls pages from J! Archive, caches them verbatim, and parses them
into JSON:

```
fetch (HTTP)  ->  cache (plaintext .html)  ->  parse  ->  output (.json)
```

```
jplay --fetch seasons                 # listseasons.php               -> listseasons.json
jplay --fetch season <season_id>      # showseason.php?season=<id>    -> season-<id>.json
jplay --fetch game <game_id>          # showgame.php?game_id=<id>     -> <id>.json
jplay --fetch player <player_id>      # showplayer.php?player_id=<id> -> player-<id>.json
```

`<season_id>` is an opaque string (`42`, `jm`, `pcj`); game and player ids are
integers. JSON is printed to stdout and written to the conventional output
file in the current directory. Cached HTML lives in the configured
`jarch_cache_dir` (default `$XDG_CACHE_HOME/jarch/`, i.e. `~/.cache/jarch/`) —
the same cache the TUI browser uses.

Flags: `--refresh` (ignore cache, re-fetch), `--out <path>` (write JSON there
instead), `--stdout` (no file), `-h`/`--help`.

Environment:

- `JARCH_DIR` — override both the cache and output directory, and disable
  index-page staleness (so fixture runs stay offline), e.g.
  `JARCH_DIR=jarch/testdata jplay --fetch game 6789 --stdout`.
- `JARCH_FETCH_DELAY` — seconds slept before each network fetch (default 2).
- `JARCH_INDEX_TTL` — seconds before a cached *index* page (`seasons`,
  `season`) is re-fetched (default 43200 = 12h; `0` caches forever). Game and
  player pages are immutable and always cached forever.

hrefs in the output are site-relative; resolve against `https://j-archive.com/`.
The full output schema is in `docs/jarch/SPEC.md`.

> J! Archive's disclaimer prohibits scraping. The fetcher is for personal,
> low-volume, incremental use only: it fetches only what it is asked for,
> cache-first, rate-limited, with a descriptive User-Agent.

## Configuration

`~/.config/jplay/config.kdl` (created only when saving from `jplay --config`):
fuzzy threshold, article/question-framing stripping, pass penalty, theme
(`term` default — respects your terminal palette — plus `rosepine`,
`rosepine-dawn`, `gruvbox`, `catppuccin` or a custom 13-role `colors {}`
block), score panel visibility, DB path, jarch cache dir, export format
(csv/json/tsv).

History lives in `~/.local/share/jplay/history.db` (XDG-aware). A game is
written in a single transaction when the end screen is reached; quitting
mid-game writes nothing.

## Development

```
nix develop        # go, gopls, gotools
CGO_ENABLED=0 go test ./...
nix build          # packages.default: one static binary, no runtime deps
```

CGO is disabled throughout: SQLite is `modernc.org/sqlite` (pure Go), HTML is
parsed with `golang.org/x/net/html`, and the KDL config format is handled by a
minimal built-in parser.

Layout:

- `jarch/` — fetcher: cache-first HTTP fetch (`jarch.go`), parsers per page
  type (`pages.go`, `game.go`, shared helpers in `common.go`, DOM view in
  `node.go`), and the `--fetch` CLI (`cli.go`). `testdata/` holds cached-page
  fixtures and `*.golden.json` outputs that the parsers must reproduce
  byte-for-byte (generated by the original bash/pup/jq implementation).
- `game/` — jarch JSON loader, fuzzy judge.
- `db/` — SQLite persistence and stat queries.
- `config/` — KDL config.
- `tui/` — bubbletea models, one file per screen; all colors flow through the
  `Theme` struct in `styles.go`.
- `docs/jarch/` — fetcher spec, design suggestions, audit notes, TODO.

Parsers use the DOM for structured parts and regexes over the raw cached HTML
for mixed-content cells (clue text, revealed-answer cells), where inline-markup
order matters and each cell is a single line in the source. Settled judgment
calls (host comments, unrevealed clues, tournament round vocabulary, …) are
recorded in `docs/jarch/SUGGESTIONS.md` and `docs/jarch/AUDIT.md`.
